H- ¿Qué sucede si cada uno utiliza el push -f?
Se pisan los cambios porque cada push -f sobrescribe la rama remota con la copia local del que lo ejecuta, pudiendo borrar los <p> que subió el compañero anterior.

 Se pierde el trabajo ya que al final queda solo lo que tenga en su historial el último en forzar el push.

Se desincroniza, el historial remoto cambia de golpe y los demás quedan desfasados en sus repositorios locales.


I- ¿Qué debo hacer para que el index.html tengas todos los <p> de los puntos 18,19 y 20 en DESARROLLO ?
Primero hay que unificar los tres <p> en TESTING (cada uno hace git pull, resuelve el conflicto en index.html dejando todos los <p> y pushea). Después se hace el merge de TESTING a DESARROLLO:

En la bash:
git checkout DESARROLLO
git pull origin DESARROLLO
git merge TESTING
git push origin DESARROLLO

Si hay conflicto en index.html, se resuelve dejando los tres <p>, y luego git add index.html, git commit y git push origin DESARROLLO.
